# Файловое хранилище

[Содержание](../../README.md) · [Место, inode и I/O](<../1. Сервер/1.1. Linux.md#диски-и-файловые-системы>)

## Где лежат файлы

Для типовой BitrixVM; подставить свой document root:

```bash
findmnt -T /home/bitrix/www/upload
df -hT /home/bitrix/www/upload
lsblk -f
```

Определить устройство, файловую систему, локальное или сетевое хранение. Если настроено объектное хранилище, проверить его endpoint, ошибки и задержки запросов отдельно.

Размеры каталогов — вне пика: `du` обходит дерево и при миллионах файлов создаёт заметный I/O.

```bash
sudo du -sh \
  /home/bitrix/www/upload \
  /home/bitrix/www/bitrix/cache \
  /home/bitrix/www/bitrix/managed_cache
```

## Ошибки и задержки

```bash
sudo journalctl -k --since '24 hours ago' --no-pager \
  | grep -Ei 'i/o error|ext4|xfs|nfs|timeout|read-only|filesystem'
pidstat -d 1 10
```

В PHP/веб-логах искать `Permission denied`, `No space left on device`, `Read-only file system`, `Stale file handle`. Сопоставить с дисковыми метриками из [Linux](<../1. Сервер/1.1. Linux.md#диски-и-файловые-системы>).

## NFS

Если используется и установлены утилиты:

```bash
findmnt -t nfs,nfs4,cifs
nfsstat -c
nfsiostat 1 5
```

Проверить retrans RPC, RTT, время выполнения операций и backlog. Первый отчёт `nfsiostat` накопительный, следующие — за интервал. Для CIFS эти NFS-утилиты неприменимы.

## Операции портала

Сравнить загрузку/скачивание одного файла, создание превью и открытие документа. Разделить передачу файла, антивирусную проверку и конвертацию. Если долго выполняется SQL, проверить обращения к `b_file`, `b_disk_object`, `b_disk_version` через [MySQL](<../1. Сервер/1.3. MySQL.md>).

Синтетические тесты записи, `fio`, очистку кешей и массовые обходы файлов не запускать как часть обычной проверки production.
