# Пример отчёта о производительности Битрикс24

Все сведения ниже вымышлены. Это пример заполнения [шаблона](report-template.md), а не результат аудита реального портала. Числа согласованы между разделами; настройки не являются рекомендациями для других установок. HAR, полные логи и файлы профилировщика для примера не создавались: вместо них в приложениях приведены учебные таблицы и выдержки.

### 3.2. Кеш браузера и влияние VPN

F01 выполнялся на том же ноутбуке и под тем же пользователем. По пять прогонов в каждом режиме; медианы в секундах.

| Сценарий | LAN, без HTTP-кеша | LAN, прогрет | VPN, без HTTP-кеша | VPN, прогрет |
| --- | --- | --- | --- | --- |
| Карточка по прямой ссылке | 7,00 | 6,20 | 12,80 | 6,80 |

Без HTTP-кеша передано 9,6 МиБ ресурсов на прогон, после прогрева — 0,7 МиБ. Ключевой ответ в VPN-прогонах не стал существенно дороже на backend: медиана PHP около 4,9 с в обоих сетевых режимах. В Network увеличилось время передачи JS/CSS. VPN заметно влияет на первоначальную загрузку, но не объясняет оставшиеся 6,2 с в LAN.

Измерения указывают на сетевой путь, но не определяют, где ограничение: клиент, туннель или VPN-шлюз. Это отдельная проверка А-03.

## 5. Прикладная производительность Битрикс24

### 5.1. Страницы, компоненты и кеширование

Для пяти прогретых LAN-прогонов карточки медиана PHP — 4,900 с, SQL — 3,100 с при 128 запросах. Пользовательский виджет доставки занимает 2,700 с, включая его SQL. Эти интервалы вложены и не складываются.

Виджет запрашивает список из 100 элементов, затем читает каждый отдельно. Повторное открытие сохраняет этот набор SQL; HTTP-кеш браузера этого не меняет. Полный двухсуточный сбор монитора Битрикса не включался: вывод ограничен выбранными запросами и профилем. Данные: [8.6](#86-счётчики-и-sql), [8.7](#87-профили-и-диагностические-записи).

### 5.3. CRM, роботы и бизнес-процессы

Для тестовой сделки проверена смена стадии: робот создания задачи выполняется один раз, повторных запусков в протоколе нет. Найденные длительные процессы ожидают согласования сотрудника; их возраст не считался активным временем PHP.

Произвольные шаблоны БП не профилировались. Поэтому отсутствие проблем в одном сценарии не распространяется на всю автоматизацию.

### 5.4. REST и интеграции

Клиент обмена 1С выполняет до 32 запросов параллельно. Рост очереди PHP-FPM совпадает с обменом в оба дня, но отдельного теста с меньшим параллелизмом нет. Установлен факт конкуренции запросов за пул; количественный вклад 1С требует проверки А-01.

В сценарии сохранения ERP вызывается синхронно из PHP: медиана ожидания внешнего ответа 3,100 с из 3,600 с PHP. Это подтверждённый вклад в задержку сохранения, не предположение по имени интеграции.
