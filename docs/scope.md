# Что проверять

[Содержание](../README.md) · [Порядок проверок](<5. Рекоммендации/audit-workflow.md>)

## Основные компоненты

Linux, фактическая СУБД, PHP/OPcache, веб-серверы, Cron/агенты, кеш и медленные операции приложения. Проверять во время замедления: отсутствие ошибок в журналах не исключает очередь или нехватку ресурсов.

## По роли в установке

| Компонент | Когда нужен |
| --- | --- |
| Redis / Memcached | Используется для кеша, сессий или Push |
| Push Server | Локальная доставка уведомлений и сообщений |
| Sphinx | Выбран как поисковый движок |
| NFS/CIFS, объектное хранилище | Файлы размещены вне локального диска |
| Балансировщик | Несколько веб-узлов или отдельный входной proxy |
| RabbitMQ / Transformer | Используется локальная конвертация документов |
| SMTP, LibreOffice, FFmpeg, ImageMagick, ClamAV | Медленная почта, обработка документов, видео или файлов |
| Winbind / Kerberos | Задержки доменной авторизации |

`sshd`, `certbot`, Ansible и подобные службы не требуют отдельного тюнинга без указаний из метрик. Проверить синхронизацию времени и ротацию журналов; сеть/firewall исследовать при задержках или обрывах соединений.

## Несколько узлов

- Сравнить нагрузку, версии и конфигурации веб-узлов; проверить распределение запросов и session affinity, если требуется схемой сессий.
- Проверить очереди, ошибки и health checks балансировщика.
- Измерить задержки между web, DB, кешем и хранилищем, а не только от клиента до портала.
- При репликации БД проверить ошибки/отставание и фактический маршрут чтения/записи. Команды выбирать для установленной СУБД и версии.
- Проверить, не выполняются ли одни фоновые задания на нескольких узлах.

В BitrixVM часть конфигураций управляется штатными средствами, включая `bvat`. Ручные правки стандартных файлов могут перезаписываться: использовать предусмотренные для версии custom includes.
