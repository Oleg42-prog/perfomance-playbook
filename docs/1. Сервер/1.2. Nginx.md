## Логи и конфигурация

```bash
nginx -v
sudo nginx -t
sudo nginx -T
sudo tail -n 200 /var/log/nginx/error.log
```

В `nginx -T` найти нужный `server` / `location`, пути журналов, upstream, `proxy_pass` или `fastcgi_pass`. Проверить, что статика не уходит в PHP. Вывод может содержать секреты.

| Ошибка | Куда смотреть |
| --- | --- |
| `upstream timed out` | Долгий PHP/SQL, очередь backend |
| `connect() failed`, `no live upstreams` | Адрес, порт, доступность backend |
| `upstream prematurely closed connection` | Завершения Apache/PHP, OOM |
| `worker_connections are not enough` | Лимит соединений на worker |
| `too many open files` | Лимиты дескрипторов процесса и службы |
| `upstream sent too big header` | Размер заголовков backend и буферы |

Параметры: `worker_processes`, `worker_connections`, `worker_rlimit_nofile`, `keepalive_timeout`, `proxy_*` / `fastcgi_*` timeouts и buffers. Соединения с upstream тоже входят в `worker_connections`. Увеличение таймаута не ускоряет backend.

## Нагрузка

```bash
ps -C nginx -o pid,ppid,%cpu,%mem,rss,cmd
pidstat -C nginx 1 10
sudo systemctl show nginx -p LimitNOFILE
ss -s
```

`pidstat` — если установлен. `ss -s` показывает соединения всего узла.

Если уже настроен локальный `stub_status`, проверить `Active`, `Reading`, `Writing`, `Waiting` и прирост разницы `accepts − handled`. `Waiting` — простаивающие keepalive-соединения, не очередь backend. `stub_status` не даёт коды ответов и p95.

## Время запросов

В access log нужны следующие поля; [конфигурация отдельного лога](<../5. Рекоммендации/request-timing.md#nginx>).

| Поле | Значение |
| --- | --- |
| `$status`, `$upstream_status` | Итоговый код и код backend |
| `$request_time` | От первых байтов запроса до завершения отправки ответа |
| `$upstream_connect_time` | Установка соединения с backend |
| `$upstream_header_time` | Получение заголовков backend |
| `$upstream_response_time` | Получение полного ответа backend |

Время в секундах. У `upstream_*` бывают `-` и несколько значений при повторах/нескольких upstream.

- 499: клиент закрыл соединение. Сопоставить с длительностью backend.
- 502/504: проверить backend и соответствующую запись error log.
- Высокий upstream time: перейти к [Apache](<1.5. Apache.md>), [PHP](<1.4. PHP.md>), [MySQL](<1.3. MySQL.md>).
- Большой разрыв между request time и upstream time: проверить загрузку тела запроса, передачу ответа клиенту и буферизацию. Это не CPU-время Nginx.

[Документация: логирование](https://nginx.org/en/docs/http/ngx_http_log_module.html)
