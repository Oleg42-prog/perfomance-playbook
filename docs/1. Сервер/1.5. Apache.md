# Apache

[Содержание](../../README.md) · [Тайминги запросов](<../5. Рекоммендации/request-timing.md#apache>)

Команды для `httpd`; в Debian-подобных системах используются `apache2ctl`, служба `apache2` и `/etc/apache2`.

## Конфигурация и ошибки

```bash
httpd -v
sudo httpd -M | grep -E 'mpm_|php|proxy_fcgi|status'
sudo httpd -t
sudo httpd -S
sudo httpd -t -D DUMP_RUN_CFG
sudo journalctl -u httpd --since '24 hours ago' --no-pager
sudo tail -n 200 /var/log/httpd/error_log
```

Искать `server reached MaxRequestWorkers`, `scoreboard is full`, segfault, ошибки выделения памяти и timeout. Причину завершений PHP смотреть также в [PHP-логах](<1.4. PHP.md>).

Найти настройки в подключаемых конфигурациях:

```bash
sudo grep -RinE \
  'MaxRequestWorkers|ServerLimit|ThreadsPerChild|ThreadLimit|Spare|MaxConnectionsPerChild|KeepAlive|Timeout' \
  /etc/httpd/conf /etc/httpd/conf.d /etc/httpd/bx
```

| MPM | Параметры |
| --- | --- |
| `prefork` | `MaxRequestWorkers`, `ServerLimit`, `MinSpareServers`, `MaxSpareServers` |
| `worker` / `event` | Также `ThreadsPerChild`, `ThreadLimit`, `MinSpareThreads`, `MaxSpareThreads` |

При prefork + mod_php каждый рабочий процесс содержит PHP. Увеличение `MaxRequestWorkers` без запаса RAM может привести к swap. Проверить также `KeepAliveTimeout`, `Timeout` и `MaxConnectionsPerChild`.

## Воркеры и память

```bash
ps -C httpd -o pid,ppid,%cpu,%mem,rss,etime,cmd --sort=-rss | head -30
pidstat -C httpd 1 10
```

RSS включает общие страницы; простая сумма завышает потребление. Ресурсы узла: [Linux](<1.1. Linux.md>).

Если `mod_status` уже настроен на локальном backend:

```bash
curl -fsS 'http://127.0.0.1:8888/server-status?auto'
```

Адрес, порт и Host взять из конфигурации. Смотреть `BusyWorkers`, `IdleWorkers`, `Scoreboard`. Постоянно занятые воркеры при нулевом резерве: найти долгие запросы и их причину, прежде чем поднимать лимит.

`ReqPerSec` — среднее с запуска, не текущий RPS. Длительность `%D` в access log измеряется в микросекундах и включает обработку PHP/backend. Сопоставлять запросы по [Request ID](<../5. Рекоммендации/request-timing.md>).
