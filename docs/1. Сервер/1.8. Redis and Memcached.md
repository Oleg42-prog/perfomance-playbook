# Redis и Memcached

[Содержание](../../README.md)

Сначала определить роль каждого экземпляра: кеш, сессии или Push. Проверить `.settings.php`, `.settings_extra.php`, `dbconn.php` и настройки веб-кластера; не копировать секреты в отчёт.

```bash
systemctl list-units --type=service --all | grep -Ei 'redis|memcached'
ps -C redis-server,memcached -o pid,%cpu,%mem,rss,etime,cmd
sudo ss -lntp | grep -E 'redis|memcached'
sudo journalctl -u redis -u redis-server -u memcached --since '24 hours ago' --no-pager
```

Искать перезапуски, OOM, отклонённые подключения и ошибки сохранения Redis.

## Redis

Примеры для localhost:6379. Порт, socket, TLS и аутентификацию взять из конфигурации.

```bash
redis-cli INFO memory
redis-cli INFO stats
redis-cli INFO clients
redis-cli INFO commandstats
redis-cli CONFIG GET maxmemory
redis-cli CONFIG GET maxmemory-policy
redis-cli SLOWLOG GET 10
```

| Метрика | Что смотреть |
| --- | --- |
| `used_memory`, `used_memory_rss`, `maxmemory` | Данные, RSS процесса и лимит; RSS может превышать `maxmemory` |
| `evicted_keys` | Прирост вытеснений; оценивать с учётом роли экземпляра |
| `keyspace_hits`, `keyspace_misses` | Попадания за интервал: `Δhits / (Δhits + Δmisses)` |
| `connected_clients`, `rejected_connections` | Подключения и прирост отказов |
| `mem_fragmentation_ratio` | Сопоставить с абсолютным RSS; на малом наборе данных отношение может быть высоким |

Низкий hit rate Push-экземпляра не означает неэффективный кеш. `SLOWLOG` измеряет выполнение команд, без сети и отправки ответа; длительность в микросекундах. Может содержать данные аргументов.

Не использовать `KEYS *`, `MONITOR`, `FLUSHALL` / `FLUSHDB` для обычной диагностики production.

## Memcached

Примеры для текстового протокола на localhost:11211:

```bash
printf 'stats\r\nquit\r\n' | nc -w 2 127.0.0.1 11211
printf 'stats settings\r\nquit\r\n' | nc -w 2 127.0.0.1 11211
printf 'stats slabs\r\nquit\r\n' | nc -w 2 127.0.0.1 11211
```

Смотреть `bytes` / `limit_maxbytes`, `curr_connections`, прирост `evictions`, `listen_disabled_num` и `get_hits` / `get_misses`. При вытеснениях проверить заполнение отдельных slab-классов, а не только общий объём памяти.

Накопительные счётчики снимать дважды под нагрузкой. Частые промахи бывают из-за TTL и сбросов кеша, а не только нехватки памяти.
