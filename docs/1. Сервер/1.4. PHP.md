# PHP и OPcache

[Содержание](../../README.md) · [Linux](<1.1. Linux.md>)

## Версия и способ запуска

```bash
php -v
php --ini
sudo httpd -M | grep -Ei 'php|proxy_fcgi|mpm_'
ps -eo pid,user,comm,args | grep -E '[p]hp-fpm|[h]ttpd|[a]pache2'
```

CLI и веб-PHP могут отличаться версией и настройками. В веб-контексте проверить `PHP_VERSION`, `PHP_SAPI`, `php_ini_loaded_file()` и `php_ini_scanned_files()`. В BitrixVM встречаются Apache + mod_php и схемы с PHP-FPM.

## Ошибки

Найти `error_log` веб-PHP; при mod_php ошибки часто попадают в журнал Apache.

```bash
sudo tail -n 200 /var/log/httpd/error_log
sudo journalctl -u httpd -u php-fpm --since '24 hours ago' --no-pager
```

Искать `Allowed memory size exhausted`, `Maximum execution time exceeded`, Fatal Error, необработанные исключения, segfault и частые одинаковые Warning.

## Настройки и OPcache

`php -i` показывает только CLI. Фактические веб-настройки получить в закрытом диагностическом обработчике:

```php
var_export([
    'memory_limit' => ini_get('memory_limit'),
    'max_execution_time' => ini_get('max_execution_time'),
    'max_input_vars' => ini_get('max_input_vars'),
    'realpath_cache_size' => ini_get('realpath_cache_size'),
    'realpath_cache_ttl' => ini_get('realpath_cache_ttl'),
]);
var_export(opcache_get_configuration());
var_export(opcache_get_status(false));
```

Последние две функции требуют установленного OPcache. Обработчик не оставлять публичным; после проверки удалить.

| Данные OPcache | Что смотреть |
| --- | --- |
| `opcache_enabled`, `cache_full` | Включён ли кеш, достигнута ли ёмкость |
| `memory_usage` | Свободная и потерянная память |
| `interned_strings_usage` | Заполнение буфера строк |
| `opcache_statistics` | Hit rate, `num_cached_keys` / `max_cached_keys`, прирост `oom_restarts` и `hash_restarts` |

Проверить `opcache.memory_consumption`, `opcache.max_accelerated_files`, `opcache.interned_strings_buffer`, `opcache.validate_timestamps`, `opcache.revalidate_freq`. При отключённой проверке timestamps обновления кода требуют сброса кеша в процессе деплоя. Веб-OPcache нельзя оценить через `php -r`.

## Процессы и PHP-FPM

```bash
ps -C httpd,apache2,php-fpm -o pid,%cpu,%mem,rss,etime,cmd --sort=-rss | head -30
```

При FPM проверить pool: `pm`, `pm.max_children`, `pm.max_requests`, `request_slowlog_timeout`, `slowlog`. Если настроен закрытый status endpoint:

```bash
curl -fsS 'http://127.0.0.1/fpm-status?json'
```

Подставить адрес из конфигурации. Смотреть `listen queue`, active/idle processes, прирост `max children reached` и `slow requests`. Очередь может быть следствием долгого SQL или внешних вызовов, а не только малого `pm.max_children`.

Медленные обработчики искать в FPM slowlog, [мониторе Битрикс24](<../3. Битрикс24/3.1. Монитор производительности.md>) или выборочным профилированием. При mod_php ресурсы PHP входят в процессы [Apache](<1.5. Apache.md>).
