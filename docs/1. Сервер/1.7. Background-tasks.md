# Фоновые задачи

## Почтовые события

SQL выполнять в БД портала:

```sql
SELECT SUCCESS_EXEC, COUNT(*) AS total
FROM b_event
GROUP BY SUCCESS_EXEC;

SELECT ID, EVENT_NAME, DATE_INSERT
FROM b_event
WHERE SUCCESS_EXEC = 'N'
ORDER BY DATE_INSERT
LIMIT 20;
```

`N` — ещё не обработано. Сравнить размер очереди и возраст старейшей записи между запусками. При задержках проверить обработчик почтовых событий, PHP-ошибки и журнал SMTP/MTA. Большая `b_event` может дорого обрабатываться даже при чтении; агрегацию не запускать частым опросом.

## Открытые линии

В расписании проверить `/bitrix/tools/imopenlines/agents.php`, если для установленной версии настроен отдельный cron-режим. Сопоставить запуски и ошибки `imopenlines` с задержками распределения диалогов. Для сообщений, которые не доходят до интерфейса, проверить [Push](<1.9. Node.js + Bitrix Push Server.md>).

## Пользовательские задания

По команде из crontab найти точку входа и журнал скрипта. Смотреть время начала/окончания, exit code, размер обрабатываемой пачки и повторные попытки. Длительный процесс без этих данных не показывает, работает он или ждёт SQL/API.

Роботы и бизнес-процессы: [отдельная проверка](<../3. Битрикс24/3.2. CRM, роботы и бизнес-процессы.md>). Они могут запускаться событиями приложения, а не только Cron.
