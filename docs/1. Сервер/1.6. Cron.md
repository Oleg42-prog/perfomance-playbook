## Расписание и запуски

```bash
systemctl status crond
sudo crontab -u bitrix -l
sudo crontab -u root -l
cat /etc/crontab
sudo grep -RinE 'php|bitrix|cron_events|imopenlines' /etc/cron.d/ /etc/crontab
systemctl list-timers --all
sudo journalctl -u crond --since '24 hours ago' --no-pager
```

В Debian-подобных системах служба называется `cron`. Проверить также пользователей, под которыми запускаются интеграции, и `/var/log/cron`, если туда пишутся журналы.

Искать дубли заданий, наложение запусков и одновременный запуск на нескольких узлах. Проверить пользователя, абсолютный путь к PHP, перенаправление stdout/stderr и блокировку повторного запуска. Cron фиксирует запуск, не успешное завершение: нужны журналы самого задания.

```bash
ps -eo pid,ppid,user,etime,%cpu,%mem,args --sort=-etime \
  | grep -E '[p]hp|[c]ron'
```

`etime` — возраст процесса, не время активной работы. Несколько одинаковых CLI-команд с перекрывающимся временем — повод проверить длительность и блокировки задания.

## Агенты Битрикс24

SQL выполнять в БД портала. Очередь готовых к запуску агентов:

```sql
SELECT COUNT(*) AS due_agents, MIN(NEXT_EXEC) AS oldest_due
FROM b_agent
WHERE ACTIVE = 'Y' AND NEXT_EXEC <= NOW();

SELECT
    ID,
    MODULE_ID,
    NAME,
    LAST_EXEC,
    NEXT_EXEC,
    AGENT_INTERVAL,
    TIMESTAMPDIFF(MINUTE, NEXT_EXEC, NOW()) AS delay_minutes
FROM b_agent
WHERE ACTIVE = 'Y' AND NEXT_EXEC <= NOW()
ORDER BY NEXT_EXEC
LIMIT 20;
```

Сравнить несколько снимков. Небольшая очередь между запусками нормальна; растущий возраст старейшего агента — нет. `LAST_EXEC` и `NEXT_EXEC` не показывают длительность выполнения.

## Где выполняются агенты

```bash
grep -nE 'BX_CRONTAB|CHK_EVENT' /home/bitrix/www/bitrix/php_interface/dbconn.php
```

Сопоставить константы с фактическим cron-обработчиком, его содержимым и настройками модуля `main`. Одного `grep` недостаточно: часть настроек задаётся в БД и пользовательском коде. Тяжёлые агенты на хитах увеличивают время пользовательских запросов.

Не запускать `cron_events.php` вручную для проверки: он выполняет реальные задания. Почта и открытые линии: [фоновые задачи](<1.7. Background-tasks.md>); автоматизация: [CRM и БП](<../3. Битрикс24/3.2. CRM, роботы и бизнес-процессы.md>).
