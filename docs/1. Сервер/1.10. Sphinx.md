# Sphinx

[Содержание](../../README.md)

Проверять, если Sphinx выбран в настройках модуля «Поиск».

## Сервис и конфигурация

```bash
searchd --help
systemctl status searchd
systemctl status sphinxsearch
ps -C searchd -o pid,%cpu,%mem,rss,etime,cmd
sudo ss -lntp | grep searchd
sudo journalctl -u searchd -u sphinxsearch --since '24 hours ago' --no-pager
```

`--help` выводит также версию. Имя службы и путь конфигурации взять из unit/аргументов процесса. В BitrixVM конфигурация часто находится в `/etc/sphinx/sphinx.conf`.

Проверить `listen`, `log`, `query_log`, пути индексов и binlog, `rt_mem_limit`, лимиты соединений. Названия параметров зависят от версии. В журналах искать OOM, timeout, `index not found`, `failed to open` / `failed to flush`.

## Запросы и индексы

SphinxQL через MySQL-протокол; пример для порта 9306:

```bash
mysql --protocol=tcp -h 127.0.0.1 -P 9306 -e 'SHOW STATUS; SHOW TABLES;'
```

Смотреть прирост `queries`, `connections`, `maxed_out`, длительность поиска (`query_wall`, `avg_query_wall`, если доступны). Параллельно проверить дисковые задержки: [Linux](<1.1. Linux.md>).

В файле `query_log` найти медленные и часто повторяющиеся запросы. Через портал проверить поиск нового или изменённого документа, права доступа и ошибки индексации.

Для RT-индексов отсутствие `indexer` в Cron нормально. Полную переиндексацию не запускать как диагностический тест.

[SphinxQL SHOW STATUS](https://sphinxsearch.com/docs/current/sphinxql-show-status.html)
