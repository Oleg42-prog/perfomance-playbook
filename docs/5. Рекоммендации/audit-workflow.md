# Порядок проверок

[Содержание](../../README.md)

1. Выбрать медленную операцию: открытие карточки, сохранение сделки, поиск. Запомнить время воспроизведения для сопоставления с логами.
2. В DevTools найти задержку: ожидание ответа, загрузка данных или работа JavaScript. Первый и повторный запросы смотреть отдельно, общий кеш портала не сбрасывать.
3. Во время замедления проверить CPU, память, диски и сеть на задействованных узлах: [команды и интерпретация Linux](<../1. Сервер/1.1. Linux.md>).
4. Сопоставить время запроса в браузере с `request_time` и `upstream_response_time` Nginx. Долгий backend: проверить занятость Apache/PHP-FPM, PHP и SQL. Быстрый ответ при медленном интерфейсе: смотреть Performance в браузере.
5. Периодические пики: проверить Cron, агентов, роботов и интеграции. Redis, Push, Sphinx и сетевое хранилище проверять, если используются.
6. После исправления повторить ту же операцию при сопоставимых нагрузке, сети и состоянии кеша.

Если задержка есть только через VPN, сравнить тот же запрос из сети клиента с одинаковым состоянием кеша: [проверки Frontend](<../2. Браузер/2.1. Frontend.md#сравнение-lan-и-vpn>). Для связи браузера и backend пригодится [Request ID](request-timing.md).

TTFB включает сеть. SQL входит во время PHP, PHP входит во время backend: эти интервалы не складываются.
